name: ql-relational
description: Use native QL event, decision, operation and harmonic receipts through the Actuation Prime faculty when a concern warrants formal QL reading.
---

Import `ql_relational` in the Prime Python kernel. The installed native faculty
and configuration are supplied through `ACTUATION_RESEARCH_BIN` and
`ACTUATION_RESEARCH_FACULTY_CONFIG`.

When installed, the six typed `ql_*` tools provide the same owner operations.
Use `/ql-mode on` to carry their exact native receipts into later reasoning and
`/ql-status` to inspect the body/session basis. `/ql-mode off` stops implicit
receipt context while preserving ordinary tools. Mode changes start no model.

Project the exact sourced event with `await ql_relational.ql_project_event(request)`.
Keep observed, derived, learned, validated and unresolved fields distinct.
Request only relevant heads. Deterministic events bypass the decision provider.

Inspect the owner-issued candidates with `ql_decision_frame(request)` and use
`ql_decide(request)` only when unresolved semantic work warrants it. An explicit
decision configuration selects AIKit execution; absent evidence stays unresolved.
Retain refusal, ambiguity and stale responses. Never overrule observed coordinates.

Invoke an accepted exact operation with `ql_invoke(envelope)`, where the envelope
uses `ql.epi-logos-agent-invocation/v1` and supplies `position`, `operation` and the
required typed `input`. The native owner validates membership and input. Use the
formal result to continue the task; retain the receipt as evidence.

Use `ql_harmonic_read(request)` for the musical rendering of formal state.
Its pitches and intervals are native projections, never model labels. Prime and
Pi consume the same QL owner; body and session identities remain separate.

All methods are explicit native calls. Importing this skill starts no classifier.
