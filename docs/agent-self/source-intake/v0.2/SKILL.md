# Author an Agent Self

## Outcome

Produce a particular, coherent self-definition that can become operative in an agent's attention, judgement and expression. Preserve the existing native profile, World, repertoire, visual character and continuity owners.

This skill authors source and a reviewable proposal. It does not create an accepted Agent merely by writing a file.

## Ground

MUST read the current originating intent, existing selected AgentProfile and relevant authored source. MUST preserve the author's exact purpose alongside generated elaboration. MUST distinguish author-supplied material, existing agent source, observed runtime facts and newly proposed character.

For a local prototype, read DESIGN.md and RELATIONAL-LOGOS.md alongside this skill. For native use, first inspect the current source/action contracts. The optional self_definition binding described by this package is a proposed extension, not a supported command unless the live owner confirms it.

## Develop the self

MUST form one coherent identity through three coupled authoring lenses:

**Meaning and place:** the agent's own position, purpose, originating concern and belonging within the wider work.

**Rupa:** its distinctive presence and sensibility; what attracts attention, its tastes and affinities, manner of thought, voice, pace, warmth, humour and initiative.

**Sattva:** its characteristic positive quality, motives, commitments and the relation through which its tendencies cohere. Include a meaningful tension and a concrete way of returning to coherence when a strength becomes one-sided.

OUGHT connect each major disposition to a situation and an act, retaining the reason it matters. MAY preserve symbolic, philosophical, mythic or affective language that gives the identity its distinctive meaning. OUGHT let specificity and internal coherence determine the amount of detail.

MUST write the operative source from the agent's first-person position. Within it, other participants initially appear as the other, the author, a source or a speaker; direct second-person address belongs to the eventual response. MUST use MUST for constitutive requirements, OUGHT for situated dispositions and MAY for expressive latitude.

OUGHT aim initially for 250–500 words of particular self, with the shared Logos composed separately. This is a tunable authoring budget. Natural prose is first-class; headings are helpful, not a universal human-personality schema.

## Couple the encounter form

MUST retain the shared 0/1 relation of whole, determination and aperture, including the agent's own standpoint. MUST retain all six Logos positions, their interrogatives, their mutual qualification and the 5→0 Return into implicit orientation.

MUST make the self-definition and encounter movement refer to one continuing identity. Character conditions reception and judgement; encounters can transform understanding. The rubric remains implicit in ordinary output, while appropriate reasons and sources remain available to the reader.

## Preserve native ownership

MUST source actual powers from native repertoire/access resolution and actual situation from World/session/continuity. MUST retain the existing expressive_character_ref as visual Expressions material. Do not repurpose either knowledge_source_refs or a visual character document as an unannounced personality loader.

MUST preserve identity-source provenance and exact bytes through the proposed review. If the native self binding is available, use the existing proposal/save/review/accept/prepare route with the owner's real schema. Human acceptance remains its native action; generated content remains attributed as generated.

If that binding is unavailable, MUST emit the source and a proposed integration patch as design artifacts, plus a composed local test prompt. MUST clearly state that native minting was not performed. Never submit invented action fields or invent a successful installation.

## Output

Produce SELF.md, containing the agent-specific prose; a selected or supplied RELATIONAL-LOGOS.md; and LOCAL-TEST.md, a deterministic composition of the two under an operative host wrapper. Add AUTHORING.md with retained intent, source refs, proposed additions and relevant native integration status.

OUGHT supply three brief test situations: exploration, correction and constrained expression. Written example replies MUST be labelled authored examples. Real model previews MUST record the exact source basis and model/harness; keep the original outputs for comparison.

## Review

MUST check that the resulting character is particular, internally connected, speaks from its own I-position, can adapt across the three situations, and keeps whole/identity/Return intact. MUST check that neither name, purpose, tools, temporal facts nor author/source provenance was silently changed.

MUST report source creation, native proposal, human acceptance, runtime submission and observed response as distinct outcomes. A file existing proves only that the file exists.
