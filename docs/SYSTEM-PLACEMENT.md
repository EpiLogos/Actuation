# Actuation in the EpiLogos system

**Status:** proposed placement, v0.2

Actuation is deliberately a developmental/referential repository rather than a new mandatory runtime tier. The actual system is a vertical composition of responsibilities, and agents may inhabit worlds at different scopes inside that composition.

Actuation has two inseparable developmental subjects:

1. first-class Agent / Agency / Actuation semantics and runtime embodiment;
2. the model / harness / agent-instance research field, including model-interior study and deliberate epistemic cultivation.

          │ WorldBinding(root agency)

          ├──────────────────────────────┐
          │                              │
          ▼                              ▼
     direct capability              Software Factory
                                     developmental need
                                           │
                                           ▼
                                 AgenticComposition demand
                                           │
                                           ▼
                                      Actuation
                                           │
                                  one or many loci
                                           │
                                           ▼
                                        AIKit

                                           │

                                           │

The diagram is a responsibility flow, not a claim that every request must traverse every product.

Model research can enter Actuation directly rather than through Factory:

```text
human / agent epistemic craft
        ↓

        ↓

        ↓
Workcell materialisation
        ↓
behaviour / interior observation / finding
        ↓
O:I projection / shared research return
```

Factory may build experimental software, but it is not required as the semantic parent of model research.

## 2. Central is residence, not semantic ownership

The personal system's ordinary agent instance should accrete with the Central world it inhabits. It may have authored identity/context material, durable preferences, histories, bindings, and machine intent rooted in that world.

That does not make Central the canonical owner of generic Agent/Agency/Actuation semantics, model research, epistemic datasets or a hidden orchestration database. Central remains the persistent human-authored ground and machine-operable filesystem/product surface. Actuation provides the reusable semantics and runtime/model experiments that let a world-bound agent be understood, studied and reproduced.

This distinction allows many possible installations:

```text
Central/
  Control/
  Work/
    project-a/    ← project-bound agent may inhabit here
    project-b/    ← another agent may inhabit here
  ...

whole Central/O:I scope
  ↑ RootAgency may inhabit this enclosing world
```

The files that express an agent's local identity or state MAY live beside its world. The portable ontology and experimental implementations do not need to be copied into every world.

## 3. O:I relation

O:I gives the whole system a selective disclosure/composition layer and an account of Objective Internality / Objective Co-Internality.

Actuation uses that interior as a possible world of agency. O:I may disclose or project:

- an Agent;
- an Agency;
- an AgenticComposition;
- a Return;
- a participant in an Actuation where disclosure is authorised;
- a research corpus or corpus revision;
- an experiment configuration or result;
- an epistemic evaluation;
- a model-interior observation or derived visualisation;
- a Structural Finding, reproduction, critique or correction.

But `Participant` is not `AgenticLocus`, and `SharedField` is not `AgenticComposition`.

An Agent may participate in an internal Actuation without being projected into a shared field. Conversely an independently grounded Other may become an O:I Participant and later enter a federated AgenticComposition without ceasing to be Other.

O:I also does not become the owner of an epistemology by projecting it. Native Actuation/QL/corpus provenance remains intact while the work becomes shareable, contestable and socially conditioned through Projection, Contribution and Encounter.

## 4. Software Factory relation

Factory answers a developmental question: what semantic work, evidence, candidates, repair, sequencing, synthesis, or execution disposition is required to progress a Project/Run?

It may conclude that the required work is best realised through a plurality of agentic loci. At that boundary Factory requests or consumes Actuation rather than defining the generic ontology of the actors it uses.

```text
Factory Run / semantic act
        ↓
Execution Intelligence
        ↓
need for one or many agentic loci
        ↓
Actuation contract
        ↓
AgenticComposition
        ↓
ExecutionDisposition enacts the composition
```

This keeps `ExecutionDisposition` valuable without overloading it. It remains the answer to **how should this developmental act be enacted?** Actuation answers **what first-class agentic whole is being constituted, who/what are its loci, how are they related, under what bounds, and how does their difference return?**

Factory may also be used to implement software required by Actuation experiments. The resulting software-development Run remains Factory-owned; the model/harness experiment and its epistemic/model-interior findings remain Actuation-owned.

The existing Epi-Logos 0/1 reader-composer and six canonical Agent identities therefore become a Factory profile/client of the generic Actuation grammar, not the definition of generic agency.

## 5. AIKit relation

AIKit resolves an operative body for each agentic locus:

```text
Agent / Agency
    ↓
Context + capabilities + model
    ↓
Harness / HarnessComposition
    ↓
AgentSession
    ↓
CLI / TUI / GUI / messaging / API / webhook Surfaces
```

Actuation does not replace this model.

The key invariant is:

> `AgenticComposition` is semantic actor plurality; `HarnessComposition` is operational body composition for an actor.

For research, AIKit also resolves the **research profile** through which an Actuation experiment becomes executable. Such a profile may select:

- model / checkpoint / adapter;
- harness;
- QL/MEF skills and sources;
- model-interior read/write/causal tools;
- training/adaptation tools;
- TDA and analysis tools;
- corpus mounts;
- experiment Actions and Surfaces.

Actuation states the scientific requirement and owns the experiment. AIKit resolves concrete capabilities/providers and manages how they are made available.

## 6. Workcell relation

Workcell provides material conditions:

- process/service lifecycle;
- storage;
- network/fabric relationships;
- service bindings;
- control plane;
- local or remote materialisation;
- GPU/accelerator and model-serving conditions where required by research.

Actuation does not give Workcell Agent ontology. A material process is not automatically an Agent, and moving an agentic locus between Workcells does not create a new semantic Agent merely because the machine changed.

A useful conformance target is that one `AgenticComposition` can span multiple Workcells and survive provider/path rematerialisation while preserving Agent, Agency, composition, authority and return provenance.

For model research, the equivalent requirement is that experiment identity and provenance survive rematerialisation across local/remote machines, serving stacks and instrumentation environments.

## 7. QL-MEF / Quaternal Logic relation

Quaternal Logic is the formal/semantic source for QL and MEF. Actuation is its principal model/harness experimental field.

The generic Actuation ontology remains number-neutral, but the research programme can use the full QL system directly.

That means more than mapping six software objects to six positions. QL supplies a language of:

- positional relativity;
- differentiation and transition;
- complement and conjugacy;
- standing/articulated faces;
- recursion and nested internality;
- return/reconstitution;
- toroidal/topological process;
- bimba/pratibimba and related formal dynamics.

MEF supplies full-field epistemic refractions rather than isolated labels. L0/L0′ can provide the minimum structured disclosure floor; the broader lens field can be used to cultivate corpora, generate dialogical material and test repeatable transformations of the same object across model behaviour and internal trajectories.

The core research relation is therefore:

```text
QL/MEF formal structure
        ↓
implicit structure already present in the human corpus
        ↓
model compression / inherited organisation
        ↕
Actuation discovery experiments
        ↕
human + agent epistemic cultivation
        ↓
corpus / dialogue / annotation / adaptation / intervention
        ↓
changed model and agent organisation
```

Actuation is where this relation is made executable. Quaternal Logic remains the canonical owner of the formal system itself.

## 8. Epistemic cultivation in the suite

Crafting epistemologies is treated as a first-class AI role rather than hidden data preparation.

The epistemic cultivator may be human, agent-assisted or collaborative. The work includes source selection, structural annotation, dataset architecture, QL/MEF disclosure design, dialogical generation, counterexamples, editorial return, model adaptation and evaluation.

The suite relation is:

```text
Quaternal Logic  → formal QL/MEF language
Actuation        → model/harness research + epistemic cultivation experiments
AIKit            → profile/tool/model/harness resolution
Workcell         → material execution
O:I              → projection, participation and shared research field
Central          → authored local/personal research ground where relevant
Factory          → software development when experiments require new software
```

This is intentionally a composition of responsibilities, not a linear pipeline that every experiment must traverse.

## 9. Why Actuation is a repository at all

The repo exists because the system needs one place where generic agency and model-bearing artificial agency can be developed independently of any one client:

```text
ontology
contracts
reference runtime seams
harness experiments
model-interior instrumentation
model / checkpoint / adapter experiments
epistemic corpora and cultivation protocols
QL/MEF model research
TDA / trajectory / representation analysis
conformance
comparative evidence
```

If those things remained inside Factory, first-class agency and model research would continue to appear as special developmental execution mechanisms. If they lived only in Central, persistent residence would be confused with runtime/research ownership. If they lived only in AIKit, scientific model/epistemic semantics would be confused with capability and harness/body resolution. If they lived in O:I, the parent disclosure/social layer would become the owner of the research it is meant to expose and relate.

Actuation is therefore a **developmental and experimental home for model-bearing agency**, while Central/O:I worlds remain natural **operative and shared homes for instances, disclosures and returns**.
