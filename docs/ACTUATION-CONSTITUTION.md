# Actuation Constitution

**Status:** proposed foundation, v0.1  
**Scope:** generic first-class agency and actuation semantics  
**Repository:** `EpiLogos/Actuation`

## 1. Purpose

Actuation is the developmental and reference home for the semantics by which an agent inhabits a world, differentiates agency within that world, relates a plurality of agentic loci, and incorporates what those loci return.

This repository is **not** a special residence that all agents must inhabit. In the EpiLogos personal system, an actual agent normally belongs with the Central world/directory whose Objective Internality it can act within. Actuation supplies the reusable ontology, contracts, reference runtimes, harness experiments, and evidence needed to make that agency explicit.

The repository therefore separates two questions that were previously easy to conflate:

1. **Where does an agent live?** — in the world to which the agent is bound; in the personal system this is ordinarily a Central world/directory.
2. **What makes an agent, its body, and its relations to other agents first-class and reproducible?** — this is Actuation's developmental subject.

## 2. Numbering is not ontology

`#0`, `#1`, `0/1`, named Epi-Logos positions, and similar coordinate labels belong to profiles or formal projections. They are not generic runtime classes.

The possible future exchange of `#0` and `#1` therefore does not alter this constitution. Generic documents MUST use semantic terms such as `RootAgency`, `WorldBinding`, `Actuation`, and `AgenticComposition`. A profile MAY map those terms to numbered or named positions.

## 3. Imported foundations

Until their ownership is deliberately migrated, Actuation consumes the existing generic distinctions already proven in the wider suite:

- `Agent` is enduring semantic identity;
- `Agency` is the situated determination of an Agent relative to role, stance, authority, capability, Context, and world;
- `AgentSession` is replaceable runtime/session continuity and is not Agent identity;
- `Execution` is one concrete act and is not Agent or Agency identity;
- a harness/body is operational constitution and is not the identity of the Agent it embodies.

Actuation MUST NOT create parallel incompatible meanings for these terms merely to establish a new repository. The ownership migration is a separate compatibility task.

## 4. Primary new relation

The missing generic relation is **Actuation**.

> **Actuation is the whole-preserving relation by which a situated Agency determines a bounded plurality of agentic loci, governs how those loci may operate and interrelate, and admits their returned difference into the world from which the determination arose.**

This is not synonymous with process spawning, task dispatch, orchestration middleware, harness composition, or Factory execution disposition. Those may enact an Actuation; they do not define its semantic identity.

An Actuation establishes an **AgenticComposition**:

> **AgenticComposition is a bounded semantic plurality of Agents and/or Agencies related as one operative whole for a purpose in a world.**

The determining position inside a composition is a **relational role**, not an Agent subtype. There is no `ManagerAgent`, `MasterAgent`, or `WorkerAgent` species in the generic ontology.

## 5. Metagency

> **Metagency is an Agency's capacity to take agency itself as an object of action: to establish, bind, configure, relate, suspend, recall, replace, or reintegrate agentic loci within its world.**

Metagency is what makes an Agentic World more than a world that merely contains multiple agents.

An **AgenticWorld** is a world in which agents, agencies, possible agencies, compositions, delegations, authority bounds, and returns are themselves addressable parts of the operative world.

A **RootAgency** is an Agency whose WorldBinding targets the enclosing Objective Internality for a scope. Rootness is positional and scoped. It does not make a new ontological species of Agent, and it does not imply that every other agent in the world was generated by the root.

## 6. Determination modes

A composition MUST be able to distinguish at least four ways a participating locus entered the composition:

- **self-differentiation** — multiple situated Agencies of the same enduring `AgentRef`;
- **delegation** — an already-existing enduring Agent enters under a bounded delegated Agency;
- **derivation** — a new enduring Agent identity is explicitly created with lineage and authority provenance;
- **federation** — an independently grounded Agent participates without becoming a derivative identity of the determining Agent.

The fourth case is constitutional. A one-to-many model that assumes every Other is generated by the governing Agent would contradict the suite's existing Self/Other and independent-participant semantics.

## 7. The determination / labour / return circuit

The philosophical master/slave language is retained as an explanatory axis but MUST NOT appear as software identity classes.

The determining or "master" moment supplies purpose, commission, scope, authority, and the relation of the many. The labouring or "slave" moment encounters actuality, resistance, evidence, error, contingency, and difference. A genuine Actuation requires both.

The same Agent may occupy a determined position relative to one composition and a determining position relative to a nested composition. Recursion is therefore a relation of scoped authority, not a caste hierarchy.

The core operational circuit is:

```text
intention
   ↓
determination
   ↓
bounded delegated autonomy
   ↓
encounter / labour / interaction
   ↓
difference + evidence
   ↓
return / convergence
   ↓
reconstituted world
   ↺
```

## 8. Constitutional laws

### 8.1 Downward authority requires upward reality

Every downward determination MUST have an admissible upward return or explicitly declared autonomous termination. A system that can command differentiated agency but cannot admit its evidence and difference is dispatch, not full Actuation.

### 8.2 Identity changes are explicit

Delegation, new Agency, new AgentSession, harness replacement, Workcell rematerialisation, Surface rebind, or provider change MUST NOT silently create a new enduring Agent identity. Derivation of a new Agent is explicit and provenance-bearing.

### 8.3 Independence survives composition

Participation in one composition MUST NOT erase independently grounded identity, local authority, provenance, or the ability to refuse actions outside granted bounds.

### 8.4 Agency is world-relative

Every situated Agency and Actuation has an explicit operative world/scope. Root Agency is simply the Agency whose scope is the enclosing world for the relevant composition.

### 8.5 Recursion preserves the same grammar

Any participating locus MAY establish a nested Actuation when its authority permits. The nested composition uses the same identity, world, determination, bounds, relation, and return semantics as the parent.

### 8.6 Material and harness neutrality

A change of model, harness component, process, machine, network path, or Workcell does not by itself change the semantic identity of an Actuation. Operational continuity and semantic identity are related through explicit provenance, not transport identity.

### 8.7 Returned difference precedes synthesis

A governing locus MUST be able to preserve attributable returned Claims, Artifacts, Evidence, Contributions, failures, and dissent before any synthesis collapses them into a single answer. Composition is not licence to erase the difference it was created to obtain.

## 9. Product boundary

Actuation owns the generic semantic relation of first-class agency, world-binding, metagency, agentic composition, determination/lineage, and return, together with reference runtimes and experiments that test those semantics.

It does **not** make the rest of the suite subordinate implementation detail:

- **Central** remains the persistent authored personal ground and ordinary residence of world-bound agents; it is not turned into a hidden scheduler.
- **O:I** owns whole-level composition, selective disclosure, Projection, Participant and co-internal relations; it may project an Actuation but does not execute it merely by disclosing it.
- **Software Factory** owns developmental semantics such as Project/Run/Run Map, evidence, candidates, repair and `ExecutionDisposition`; it may demand or employ an AgenticComposition but no longer owns the generic QL agent runtime simply because the experiments began there.
- **AIKit** resolves Context, capabilities, models, `HarnessComposition`, AgentSession and Surfaces for an operative locus. `HarnessComposition` is the body of an actor, not the semantic plurality of actors.
- **Workcell** materialises processes, services, storage, networking and lifecycle without defining Agent or Actuation identity.
- **QL-MEF** may provide formal/refraction projections over Actuation, including bimba/pratibimba and QL recurrence profiles, without making those profile terms mandatory generic primitives.

## 10. Development rule

Actuation should become more concrete by proving this grammar through executable runtimes and interop, not by accumulating speculative class names.

The first imported proving body is the QL Agent Runtime Experiment programme formerly developed under Software Factory. Its migration establishes that recurrence and agentic actuation are first-class experimental concerns while Factory remains a consumer of agentic capability for developmental work.
